# Trips in Pocket

Implemented locally. Nothing has been pushed to GitHub or deployed to the VPS.

## Using trips

1. Open **Trips** in the navigation, then **Create trip**. Enter a name, and optionally a destination and travel dates.
2. Open the card to add expenses, money lent, or reminders. The visible **Trip** field preselects this trip. The trip journal has the same search, month, type, repayment, and total controls as the main journal.
3. Use **Make active** for the default on the main entry form and Mac quick-entry popup. Only one trip can be active in an account. Selecting a new active trip never moves existing records or overwrites an open draft.
4. Choose **No trip** to make an unassigned entry. Use **Edit** to assign, move, or remove a trip on any existing entry.
5. **Mark completed** clears that trip as the default but keeps records editable. Late receipts, repayments, and reminders still work. **Reopen trip** opens it again; it does not automatically activate it.

Example: a ₹3,000 Goa flight recorded in September and a ₹200 dinner recorded in November produce ₹3,200 of trip spending. The main dashboard still includes each expense only in its recorded month. A ₹500 loan to a friend adds to money to collect, not spending; a ₹200 repayment leaves ₹300 outstanding in both views.

Mandates have no trip assignment. Their paid expenses can be manually assigned through Edit. There is no mandate creation or mandate tab in the trip journal. The main journal's named-trip filter shows no mandates, because mandates themselves do not belong to trips.

## Storage and compatibility

- `GET /trips` and `GET /trips/<UUID>` use the common page/form. Production pages require the account session; the local server keeps its loopback-only single-user model.
- `POST /api/trips` accepts `name`, optional `destination`, `startDate`, `endDate`, and an existing `id` for edits.
- `POST /api/trip-status` accepts an owned `id` and `action`: `activate`, `deactivate`, `complete`, or `reopen`.
- Existing authentication, origin/CSRF checks, and private account ledger selection apply to all new endpoints. Trip and entry IDs cannot select another account.
- Each private `ledger.sqlite3` gains `trips` and `settings` tables through a repeatable additive upgrade. Existing entry JSON is not rewritten by the upgrade. The active ID is stored under `activeTripId`; trip IDs are generated by the server.
- State and JSON exports now use schema version 4, including `trips`, `activeTripId`, optional entry `tripId`, and recoverable `trash` records. Existing older records may omit `tripId`; this means no trip. Explicit `null` or an empty string removes assignment. Missing `tripId` preserves assignment on edits and leaves new entries unassigned.
- The server never applies a default invisibly. The form submits its reviewed selection. Payments created by mandates never inherit the active trip.
- Database backups/restores already copy complete ledgers, so they automatically include trips and settings. Restoration into a new directory was tested for the owner and another account.
- Obsidian's generated ledger now includes trip labels on expenses, loans, repayments, and reminders, plus a trip summary. Totals do not add trip summaries back into overall spending. The owner-only endpoint and existing Mac helper configuration are unchanged.

## Local update

Restart the local Pocket server and refresh the page to see **Journal · Trips**. Opening `index.html` directly does not start the app. A running older Python process must be restarted because only static assets refresh from disk.

Before a future VPS update, make the existing full database backup, update the app files together, and restart the existing PM2 service. No new packages, sync token, vault path, Nginx location, or Obsidian LaunchAgent are required. The Mac companion loads the shared `/quick-entry` form from the server, so its selector becomes available after that web update. This implementation has not deployed anything.

## Verification

Passed locally:

- 36 Node tests: parsing, form submission, popup keyboard handling, defaults, explicit No trip, completed-trip selection, refresh/draft preservation, filters, totals, and duplicate submission guards.
- 70 Python tests: the 59 existing regression checks plus 11 trip checks covering both server modes, additive upgrades, cross-month entries, partial/full repayments, reminders, mandate assignment, concurrent defaults, account isolation, CSRF, validated login/signup returns, backups/restores, and owner-only Obsidian sync to a temporary vault.
- JavaScript/Python syntax and Git whitespace checks.

The responsive styles cover cards, navigation, trip dialogs, the main journal, and the compact popup. Actual rendered desktop/phone/popup and keyboard layout checks remain **unverified**: the environment denied Chromium's macOS Mach-port registration before a browser window could open. No screenshots or visual passes are claimed.

The isolated browser scenario is prepared in `tests/trips_browser.cjs`. With Playwright and its browser installed in a permitted environment, run from this directory:

```bash
.venv/bin/python -m unittest discover -p 'test_*.py'
node --test test_*.js
POCKET_TEST_PYTHON="$PWD/.venv/bin/python" node tests/trips_browser.cjs
```

The browser test uses synthetic records and a disposable Flask fixture over a local process pipe. It checks 320, 390, 480, 768, and 1280 pixel widths, creation/editing, defaults, combined filters, totals, popup shortcuts, repayments, completion, reassignment, dialog keyboard behavior, and absence of browser record storage. It does not contact the VPS or your real vault. Set `POCKET_SCREENSHOT_DIR` to a temporary output directory for screenshots. `POCKET_BROWSER` can select another installed Playwright engine.
